# شجرة عفرين

منصة رقمية لحفظ شجرة العائلات والتاريخ الاجتماعي والصور القديمة لمنطقة عفرين.

## 1. رؤية المشروع

إنشاء أرشيف رقمي طويل الأمد يجمع:

- شجرة العائلات.
- الأشخاص والعلاقات العائلية.
- القرى والمدن التابعة لمنطقة عفرين.
- الصور التاريخية.
- قصص العائلات والقرى.
- مصادر المعلومات والتوثيق.

المشروع ليس شبكة تواصل اجتماعي، بل أرشيف تاريخي منظم يخضع للمراجعة قبل النشر.

## 2. أهداف المشروع

- حفظ الأنساب من الضياع.
- ربط الأشخاص بعائلاتهم وقراهم.
- حفظ الصور التاريخية القديمة.
- التعرف على الأشخاص الموجودين داخل الصور.
- توثيق القصص والأحداث المحلية.
- منع المعلومات المكررة أو غير الدقيقة.
- حماية خصوصية الأشخاص الأحياء.
- توفير البحث باللغة العربية والكردية واللاتينية.

## 3. نطاق الإصدار الأول

يتضمن الإصدار الأول:

1. تسجيل المستخدمين.
2. تسجيل الدخول.
3. البحث عن الأشخاص.
4. عرض صفحة الشخص.
5. إضافة شخص جديد.
6. إضافة علاقات عائلية.
7. رفع صورة تاريخية.
8. ربط الأشخاص بالصور.
9. إرسال طلبات تصحيح.
10. مراجعة كل الطلبات من الإدارة.
11. صفحات القرى والمدن.
12. أرقام تعريف داخلية للأشخاص والمواقع والصور.

## 4. المعرفات الداخلية

### الأشخاص

مثال:

AFR-000001

### المواقع

مثال:

LOC-0001

### الصور

مثال:

IMG-000001

### العائلات

مثال:

FAM-000001

لا يعتمد النظام على الاسم وحده، لأن عدة أشخاص قد يحملون الاسم نفسه.

## 5. القرى والمدن

سيشمل المشروع جميع القرى والمدن البالغ عددها 366.

التنظيم:

منطقة عفرين
→ الناحية
→ المدينة أو البلدة أو القرية

كل موقع قد يحتوي على:

- الاسم بالعربية.
- الاسم بالكردية.
- الاسم بالأحرف اللاتينية.
- أسماء بديلة أو تاريخية.
- نوع الموقع.
- الناحية التابعة لها.
- ملاحظات تاريخية.

## 6. معلومات الشخص

قد يحتوي سجل الشخص على:

- الاسم الأول.
- اسم الأب.
- اسم الجد.
- اسم العائلة أو الكنية.
- الجنس.
- حالة الحياة.
- سنة الميلاد.
- تاريخ الميلاد.
- سنة الوفاة.
- تاريخ الوفاة.
- القرية الأصلية.
- مكان الولادة.
- أماكن الإقامة.
- المهنة.
- السيرة المختصرة.
- الأب.
- الأم.
- الأزواج.
- الأبناء.
- الإخوة.
- الصور التاريخية المرتبطة.
- مصادر المعلومات.
- مستوى الثقة بالمعلومات.

## 7. الخصوصية

لكل معلومة مستوى ظهور مستقل:

- public: عام.
- registered: للمستخدمين المسجلين.
- private: لصاحب السجل والإدارة.
- hidden: مخفي.

بيانات الاتصال والعنوان والوثائق لا تظهر للعامة.

يطبق النظام حماية خاصة على:

- الأشخاص الأحياء.
- الأطفال.
- العناوين الحالية.
- أرقام الهواتف.
- البريد الإلكتروني.
- الوثائق الرسمية.
- المعلومات الحساسة.

## 8. ملكية سجل الشخص

يمكن للشخص الضغط على:

"هذا السجل يخصني"

ثم يرسل طلب إثبات.

بعد موافقة الإدارة يستطيع:

- اقتراح تعديل بياناته.
- اختيار خصوصية معلوماته.
- طلب إخفاء معلومات محددة.
- إدارة موافقته على الصور المرتبطة به.

لا يتم حذف العلاقات العائلية مباشرة، بل ترسل للمراجعة.

## 9. الصور التاريخية

كل صورة تاريخية تحتوي على:

- رقم الصورة.
- عنوان الصورة.
- وصفها.
- السنة أو الفترة التقريبية.
- القرية أو الموقع.
- المناسبة.
- مالك النسخة الأصلية.
- مصدر الصورة.
- الأشخاص الظاهرون فيها.
- الأشخاص غير المعروفين.
- قصة الصورة.
- حالة المراجعة.
- مستوى الخصوصية.

يمكن للمستخدم تحديد موضع شخص داخل الصورة واقتراح هويته.

كل اقتراح يحتاج إلى مراجعة قبل النشر.

## 10. نظام المراجعة

كل إضافة أو تعديل يمر بحالة:

- draft: مسودة.
- pending: بانتظار المراجعة.
- approved: معتمد.
- rejected: مرفوض.
- archived: مؤرشف.

الإدارة تستطيع:

- الموافقة.
- الرفض.
- طلب توضيح.
- تعديل الطلب.
- دمج الأشخاص المكررين.
- استعادة النسخ السابقة.
- إخفاء المحتوى.
- حظر المستخدمين المسيئين.

## 11. الصلاحيات

### الزائر

- البحث.
- مشاهدة المحتوى العام.

### المستخدم المسجل

- اقتراح أشخاص.
- اقتراح علاقات.
- رفع صور.
- اقتراح تعديلات.
- طلب امتلاك سجل شخص.

### المراجع مستقبلًا

- مراجعة الطلبات المخصصة له.
- إرسال توصية للإدارة.

### المدير

- التحكم الكامل.
- اعتماد المحتوى.
- إدارة المستخدمين.
- دمج السجلات.
- إدارة القرى والعائلات.
- الاطلاع على سجل التعديلات.

في البداية يوجد مدير واحد فقط وهو مالك المشروع.

## 13. مبادئ تقنية

- قاعدة البيانات: PostgreSQL عبر Supabase.
- الحسابات: Supabase Auth.
- الصور والملفات: Supabase Storage.
- الواجهة: تبدأ بـ HTML وCSS وJavaScript.
- يمكن الانتقال لاحقًا إلى React أو Next.js.
- دعم الهاتف أولًا.
- دعم اللغة العربية واتجاه RTL.
- حفظ سجل كامل للتعديلات.
- عدم حذف السجلات نهائيًا إلا في حالات خاصة.

## 14. مراحل التنفيذ

### المرحلة الأولى

- الصفحة الرئيسية.
- التصميم الأساسي.
- البحث التجريبي.
- صفحات الأشخاص والقرى والصور.

### المرحلة الثانية

- إنشاء Supabase.
- تسجيل المستخدمين.
- إنشاء قاعدة البيانات.
- إضافة الأشخاص والقرى.

### المرحلة الثالثة

- العلاقات العائلية.
- شجرة تفاعلية.
- الصور التاريخية.
- تحديد الأشخاص داخل الصور.

### المرحلة الرابعة

- لوحة الإدارة.
- المراجعة والموافقة.
- كشف السجلات المكررة.
- سجل التعديلات.

### المرحلة الخامسة

- اللغات الإضافية.
- التوسع في الأرشيف.
- تعيين مراجعين.
- تحسين البحث والأداء.

## 15. القرارات المعتمدة

- اسم المشروع: شجرة عفرين.
- عدد القرى والمدن المستهدف: 366.
- معرف الشخص: AFR-000001.
- معرف الموقع: LOC-0001.
- المالك هو المدير الوحيد في البداية.
- كل إضافة وتعديل يحتاجان إلى مراجعة.
- الخصوصية تطبق على مستوى كل معلومة.
- الصور المستخدمة تاريخية وأرشيفية بالدرجة الأولى.
